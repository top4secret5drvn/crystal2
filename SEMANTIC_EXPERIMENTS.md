# Проверка контекстно-геометрической памяти

## 1. Что реализовано

Аудит выполнен на origin/main `1dd4f80` до изменений. Исправлены основания
этапа 1; изолированный SemanticSpace проверен до подключения к ядру.
Далее добавлены три режима, поддержка снимков и контроль структурного сна.
Архитектура и стратегия миграции: [SEMANTIC_ARCHITECTURE.md](SEMANTIC_ARCHITECTURE.md).
41 автоматический тест проходят, включая прежние 18 регрессий.
Внешней сети, Wikipedia и ML-зависимостей для проверки не требуется.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 python3 examples/semantic_memory.py
PYTHONDONTWRITEBYTECODE=1 python3 tests/semantic_benchmark.py
```

Сырые измерения всех 36 запусков: [semantic_results.json](experiments/semantic_results.json).
Последняя команда печатает новый JSON, не перезаписывая сохраненный результат.

## 2. Методика без тестовых ответов в обучении

Seeds 17, 29, 43; K=3; 8 синтетических групп по 8 объектов.
Разделение целевых ответов: 32 train, 16 validation, 16 test для каждого seed.
Заранее фиксированы 120 итераций, шаг 0.04, бюджет 100000 координатных операций.
Размерности сравниваются как экспериментальные варианты; лучший вариант по тесту
не выбирается в качестве нового default. Default остается **off**.
Порог бинарного переноса скрытого свойства выбирается только на validation
из фиксированного набора 0.4, 0.5, 0.6. Test labels читаются после предсказаний.

Каждый объект получает неполный набор подтвержденных типовых признаков своей
синтетической группы. Неизвестное скрытое свойство задано генератором; его ответы
не поступают в координатную оптимизацию и не появляются среди известных признаков.
Train labels используются только для взвешенного переноса от K соседей.
Это явный исследовательский предсказатель гипотез в harness, не новая подсистема
достоверного логического вывода. Он не записывает предсказания как факты.
Не утверждается автономное открытие новых предикатов или значений слов.

**Трансдуктивный протокол входных структур:** известные признаки validation/test
объектов доступны оптимизатору, их целевые ответы недоступны. Это не проверка
индуктивного размещения полностью нового объекта без повторной тренировки.
Метрики нельзя выдавать за такое обобщение. Отдельный пример показывает обновление
координат после добавления нового свидетельства и повторного обучения.

Baseline — исправленный типизированный граф без координат: Jaccard известных
признаков. Остальные варианты используют ту же информацию и exp(-distance)
с поправкой на качество/поддержку. Для всех используется одинаковый train-label
предсказатель. Precision@3 вычисляется относительно скрытой группы, только среди
train-кандидатов для test-запросов; недостающие соседи считаются промахами.
Accuracy учитывает abstention как отсутствие правильного ответа, но оно отдельно
считается unknown, а не ложным наблюдением. FP — положительный ответ при отрицательном
скрытом свойстве; это ложная гипотеза harness, не записанный факт Кристалла.

Условия: normal — пропущено в среднем 15% признаков; incomplete — 55%; contradictory
дополнительно содержит независимое равносильное отрицание признака с индексом 0.
Обе модели используют одинаковое разрешение конфликтов: такой признак неизвестен.
Отрицательное свидетельство сохраняется в provenance графа и геометрической истории.
Отсутствие связи не превращается в несовместимость.

Для каждого запуска измерены полный размер `.cry` после сна, wall time,
peak Python allocations под tracemalloc, дополнительные узлы при повторном сне,
дубликаты состава и межмировые ошибки. Это три малых опыта, а не статистически
значимое исследование скорости. Время включает подготовку, сон и сохранение;
tracemalloc добавляет накладные расходы, его память не равна RSS.

## 4. Эксперименты A–E

A. Яблоко и апельсин с общим подтвержденным IS_A фрукт приобретают близкие,
но разные позиции и разные sense_id. Дерево IS_A растение само по себе не дает
сравнительной позиции: необходим дополнительный структурный сигнал; ответ unknown.
Подтвержденный факт о классе не теряется из-за отсутствия координат.

B. «Однако» и «потому что» имеют общее назначение connective и отдельные
подтвержденные функции opposition/explanation. Координаты могут сближаться
по общей функции, но функции и значения не сливаются; в предметном мире
сходство отсутствует. Это контролируемые функциональные данные, не доказательство
самостоятельного понимания русского причинного объяснения.

C. Три значения «ключ» имеют разные ID и признаки. Без контекста остаются
три кандидата; контекстные типовые признаки выбирают одно. Совпадение лексемы
не создает близость между значениями. Один sense может принадлежать нескольким
мирам; при отсутствии позиции возвращается None.

D. Тест переноса скрытого свойства описан выше. Граф на normal уже дает 1.0;
3D заметно хуже. Это отрицательный результат для гипотезы о пользе выбранной
геометрии. Параметры не подгонялись после просмотра test.

E. Отдельные тесты последовательно добавляют факты, запускают сон, сохраняют
и читают full/delta. Повтор без нового provenance/топологии не создает узлов и
не усиливает воспоминания; DAG остается без самовключения. Новая многоуровневая
комбинация разрешена, повтор и обертка своего подмножества отвергаются.
До исправления тест воспроизводил рост 31 → 79 узлов за повторные циклы без данных.
Сейчас этот тест стабилен. Legacy bundled .cry читаются; отдельно проверено чтение
новой binary projection старым reader `1dd4f80`. Старый reader теряет расширенный
слой при обратной записи, поэтому downgrade требует копии.

## 5. Реальное изменение координат

Команда examples/semantic_memory.py сначала обучает яблоко и апельсин по общему
подтвержденному классу. Затем добавляет новое подтвержденное отношение для абрикоса
и продолжает оптимизацию. Новые координаты не задаются примером вручную.

- Яблоко до: `[-0.200687, -0.073005, 0.573421]`.
- После: `[-0.310374, 0.085144, 0.150209]`.

Полный вывод: [coordinate_update.json](experiments/coordinate_update.json).
Изменение координат само по себе не считается улучшением знаний: полезность
оценивается независимыми метриками, приведенными выше.

## 6. Ограничения и неподтвержденные гипотезы

- 3D **не превосходит граф**. В normal точность ~0.54 против 1.0. Наличие
  только положительных локальных ограничений оставляет взаимное расположение
  независимых сообществ слабо определенным. Начальная случайная близость может
  давать ложных соседей; отсутствие связи нельзя использовать как отрицательный
  пример ради красивого разделения. Три оси могут искажать многомерные отношения.
- 8D лучше 2D/3D на этих данных, но не дает устойчивого выигрыша над графом:
  в normal совпадает по accuracy и уступает P@3; в incomplete точнее ищет соседей,
  но не повышает hidden accuracy. Размер состояния и время больше. Экспериментальное
  преимущество геометрической памяти относительно простого графа **не подтверждено**.
- SemanticSpace требует предоставленных значений, ролей, миров и подтвержденных
  свидетельств. Sense/world induction из сырого текста не реализован. Начальные
  два пространства — fixture алгоритма, не универсальная классификация знаний.
- Автоматическое подтверждение внешних источников, калибровка confidence и
  сквозная ревизия всех старых путей вывода не решены этой работой.
- Нет доказательства достаточности 3D; нет калиброванной вероятности правильности
  из геометрического score. Объекты без обученной позиции остаются unknown.
- Корпус мал и искусственно структурирован; мало seed. Нулевые межмировые ошибки
  во многом обеспечены явной проверкой world/role, а не обученной дисамбигуацией.
- Проекция для энергии сохраняет одно отношение на соседа. Полный набор доступен
  типовым запросам, но старое планирование не стало полным многотипным доказателем.
- Legacy hdc_vector не переписывается; старые ошибки эпох не реконструируются.
  Не все transient runtime-структуры входят в snapshot; поврежденная загрузка
  пока не транзакционная. Большие многолетние графы не исследованы.

Следующие проверяемые гипотезы: получить независимые отрицательные ограничения
через эксперимент, измерить inductive out-of-sample placement с замороженными
anchors, проверить несколько семейств графов и более широкий список seed.
Эти идеи **не реализованы** и не используются для объяснения текущих метрик задним числом.
До таких проверок рекомендуемый режим — off либо diagnostic, а не доверие
геометрическому ранжированию как источнику фактов.
