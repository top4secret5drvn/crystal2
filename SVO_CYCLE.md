# Восстановление SVO-цикла

## Аудит и воспроизведение

База: актуальный main `7cafa74`, включающий предыдущие исправления и обучение
правил. Ветка `fix/svo-observation-cycle`.

CommandSession выполнял инжекцию, обратную волну и затем вызывал response_policy.
Обратная волна сама по себе не создавала семантического утверждения. Мембрана
формировала SYN; semantic_rules узнавал только буквальные маркеры и определения.
Для «ест» и «нагревает» не существовало модели отношения. response_policy
разбирал именные запросы, но не переменную субъекта/объекта. Типизированный граф
правильно сохранял несколько бинарных типов, однако ни один из них не означает
произвольное действие. Объявление «нагревает» CAUSE было бы ошибкой.

«Солнце это звезда» уже работало через IS_A и Attributed. Этот случай сохранен,
а не объявлен новым достижением. Четыре первоначальных регрессионных теста
провалились на main; результат сравнения каждой отдельной пары записан в
`experiments/svo_cycle.json`. Команда воспроизведения поддерживает --source,
поэтому baseline проверен тем же скриптом, а не вымышленными значениями.

## Минимальная реализация

- `svo_grammar.json` — открытый словарь **языковых форм**, без знаний о том,
  кто кого ест, читает или нагревает. Восемь предикатов, настоящее время,
  один токен субъекта и объекта; отрицание и начальная модальность сохраняются.
  Расширение форм возможно данными без веток под учебные предложения.
- `svo_observations.py` — ограниченный SVO-разбор и заполнение переменного слота
  вопроса по имеющимся фреймам. Используется прежний SemanticFrame и его
  существующий snapshot-store, а не второе хранилище фактов.
- `semantic_rules.py` — SVO как fallback после прежних правил. Фрейм хранит
  subject/object/predicate в нормализованной форме, отдельные surface-формы,
  исходное предложение, context/world/source, timestamp логического такта,
  polarity/modality/status/confidence, provenance_id и реальные subject_id/object_id.
- `response_policy.py` — маршрутизация до именного поиска. «Кто …?» ищет субъект,
  «что …?» допускает поиск обоих слотов по имеющимся аргументам. Если обе трактовки
  подходят, результат Unknown, а не выбор по энергии. Прямой SVO-вопрос проверяет
  всю тройку. Verified не принимает observed, confidence не превышает 0.6.
- `engine.py` — сон сохраняет узлы, на которые ссылаются семантические фреймы.
  Защищены также явные алиасы; физика распространения энергии не меняется.
- `membrane.py` — recognized semantic_frames, newly created semantic_relations,
  parse_errors и parse_error_reasons. Число фреймовых отношений не означает число
  новых бинарных ребер: SYN остается отдельной статистикой.
- `research.py` — источник передается в создание фрейма до вычисления provenance_id;
  временный source восстанавливается даже при исключении. Разные источники
  сохраняются отдельно, повтор одного документа не умножает уверенность.
- `structured_observations.py` — сохраняет отдельную причину SVO-отказа.

SVO — вид существующего фрейма, **не новый бинарный EDGE-код**. Семантическая
связь субъект–предикат–объект представлена самим фреймом с указателями на узлы.
Обычный просмотр бинарного графа продолжает показывать SYN и прочие прежние типы;
полная доказательная связь доступна в relations ответа/semantic_frames отчета.
Нет искусственного CAUSE, новой онтологии действий или миграции бинарной матрицы.

TypedConnections не менялся: его мультисвязность не являлась причиной этих отказов.
ImitationLearner не менялся: он не должен создавать отсутствующее действие
подстройкой генератора. SVO не предлагается к мутациям бинарных типов через
прежнюю вкладку вопросов: для этого нужна отдельная проверка корректности грамматики.
Старые .cry/.cdt используют прежний сериализатор semantic_rules_state, поэтому
новые поля фреймов сохраняются без смены MAGIC/schema. Старые фреймы не требуют
добавления новых полей: поиск обрабатывает только relation=SVO.

## Истина, отрицание, контексты

Введенная фраза — observed, не confirmed. Даже положительный ответ прямой
проверки означает «согласно наблюдению», а не независимое доказательство.
Отрицательный фрейм никогда не используется как положительный объектный ответ.
Одинаковая тройка с противоположной полярностью в применимой области дает
Unknown/conflict. Несколько разных объектов действия сами по себе не объявляются
противоречием, но единичный ответ не выбирается произвольно.

Используется общий context_applies: глобальные наблюдения наследуются, источники
source_observation доступны внутри исходной смысловой области; отдельный
диалоговый контекст не переносится в global. Источник не равен области действия.
Ни число повторов, ни энергия резонатора не увеличивают confidence.

Нормализация явная и ограниченная: casefold/ё→е, формы глагола из данных,
парадигмы земля/землю, звезда/звезды/звёзды, рыба/рыбу, слово/словом. Это лексические
данные, не таблица ответов: никакого соответствия предиката субъекту/объекту в них
нет. Незарегистрированная форма сохраняется без угадывания леммы. Нет общего
отрезания окончаний или объединения коротких основ. Поверхностная форма сохраняется
для ответа («рыбу», а не искусственное «рыба»). Несколько привязанных senses
приводят к Unknown; автоматическое разрешение омонимии здесь не реализовано.

Пример настоящего текста: «По наблюдению “direct text input”: рыбу.

predicate=есть, provenance_id, контекст, источник, tick, status, confidence и слот.
Полные тексты и статистика — `experiments/svo_cycle.json`.

102 unit/API-теста прошли, включая 9 новых тестов: A–J, конфликт/отрицание,
прямую проверку, strict Verified, снапшот, отдельные источники, повторение,
истинный CLI-путь, сон и диагностику. Существующий Chromium-сценарий исследования
и имитации также прошел. Проверки выполнены на Linux/Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_svo_cycle.py
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe tests\svo_reproduction.py
.\.venv\Scripts\python.exe -m crystal_lab --workspace .\lab-data
```

В Lab выполните `ввод кот ест рыбу`, затем задайте «что ест кот?» в панели
вопроса. Можно также выполнить `спроси что ест кот?` / `ответь`. Сравните Auto
и Verified. В панели доказательств показан тот же реальный фрейм.
Windows здесь не исполнялся; зависимости и локальные ограничения запуска прежние.

## Ограничения

Это конечная грамматика, не универсальный русский парсер. Неизвестные глаголы,
падежи вне зарегистрированных форм, длинные именные группы, сложные предложения,
пассивный залог, местоименная анафора и нестандартный порядок слов не распознаются.
Отказ содержит причину; raw text и ассоциации могут оставаться в памяти.
Предикатный словарь расширяем, но автоматически не обучается в этой итерации.
Нет нового механизма доказательства причинности или подтверждения наблюдений.

Источник истины для SVO — существующий журнал фреймов, ограниченный 1000 записями.
После вытеснения фрейма старые лексические SYN не восстанавливают его смысл.
Уверенность — ограниченная эвристика, не статистически откалиброванная вероятность.
Не заявляется измерение качества на произвольном корпусе русского языка.
